# md-to-excalidraw

Превращает markdown-документ в навигируемую сцену `.excalidraw`: обзорный фрейм
с кликабельной карточкой на каждый раздел и по фрейму на раздел со ссылкой
обратно. Клик по карточке зумит вьюпорт на нужный фрейм — то, что нужно для
записи скринкаста по схеме.

Зависимостей нет, только Node (в репозитории уже требуется ≥18).

Этот файл — краткая справка. Подробный разбор внутреннего устройства
(разбор markdown, генерация id, раскладка, механика ссылок-переходов) и
расширенный runbook — в [`HOW_IT_WORKS.md`](./HOW_IT_WORKS.md). Если нужно не
писать целевой markdown вручную, а получить его из произвольного текста/отчёта
— см. скилл [`md-to-excalidraw`](../../.claude/skills/md-to-excalidraw/SKILL.md).

## Запуск

```bash
node tools/md-to-excalidraw/index.mjs отчёт.md \
  --base-url https://draw.alexshein.com \
  -o отчёт.excalidraw
```

Дальше открыть `draw.alexshein.com` и перетащить файл на холст.

### `--base-url` обязателен и должен совпадать с хостом

Excalidraw считает ссылку внутренним переходом, только если её хост совпадает с
хостом открытой страницы — см. `isElementLink` в
`packages/element/src/elementLink.ts`. Ссылки генерируются в виде
`<base-url>/?element=<id элемента>`, и `App.viewport.ts` резолвит такой id в
границы элемента, на которые наводит камеру.

Отсюда практическое следствие: если сгенерировать сцену с
`--base-url https://draw.alexshein.com`, а открыть её локально через `file://`
или на другом домене, переходы работать не будут — ссылки станут обычными
внешними и откроются в новой вкладке.

## Формат markdown

```markdown
# Заголовок схемы

Абзацы до первого `##` попадают в обзорный фрейм как подпись.

## Название раздела

### Подзаголовок внутри фрейма
- пункт списка
- ещё пункт

## Следующий раздел

- пункты
```

- `#` — заголовок сцены, он же надпись на центральном узле обзора.
- `##` — один раздел = один фрейм = одна кликабельная карточка в обзоре.
- `###` — подзаголовок внутри фрейма, крупнее обычного пункта.
- `-`, `*`, `1.` и обычные абзацы внутри раздела — строки списка.
- Блоки кода, картинки, горизонтальные линейки и сноски вида `[1]`
  выбрасываются. Инлайновая разметка (`**жирный**`, `` `код` ``, ссылки)
  разворачивается в обычный текст.

Разделов может быть сколько угодно: обзор раскладывает карточки в две колонки
вокруг центрального узла, фреймы разделов — сеткой по три в ряд.

## Что стоит знать

**Вывод детерминирован.** Одинаковый вход даёт побайтово одинаковый файл, и id
элементов не меняются между запусками. Значит сцену можно перегенерировать после
правки текста, не потеряв ссылки. Обратная сторона: правки, сделанные руками на
холсте, при перегенерации затрутся — дорабатывайте вручную в последнюю очередь.

**Размеры текста считаются приблизительно.** Ничего не перемеряет шрифт при
импорте, поэтому ширина блоков оценивается по числу символов с запасом
(`CHAR_WIDTH_RATIO`). Если строка выглядит тесно — правьте на холсте руками.

**Стрелки не привязаны к фигурам.** `startBinding`/`endBinding` оставлены
пустыми: стрелка нарисована по координатам и не потянется за карточкой, если её
подвинуть. Достаточно один раз потянуть конец стрелки на холсте, чтобы Excalidraw
привязал её сам.

## Проверки

```bash
node --test tools/md-to-excalidraw/check.mjs
```

Файл назван `check.mjs`, а не `*.test.mjs`, намеренно: иначе его подхватит
vitest в `yarn test` и попытается выполнить как свой тест.

Проверяется разбор markdown, уникальность id, что каждая ссылка ведёт на
существующий фрейм, что содержимое не вылезает за границы своего фрейма, что
фреймы не наезжают друг на друга, и что вывод детерминирован.

## Пример

`example.md` — пример входного файла, на нём удобно посмотреть результат:

```bash
node tools/md-to-excalidraw/index.mjs tools/md-to-excalidraw/example.md \
  --base-url https://draw.alexshein.com -o /tmp/example.excalidraw
```
