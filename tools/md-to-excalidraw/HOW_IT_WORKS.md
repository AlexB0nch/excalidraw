# Как устроен md-to-excalidraw

Этот документ — про внутренности `index.mjs` и про то, как им пользоваться в
работе. Короткую версию (формат входа, одна команда) см. в `README.md` рядом.

## Конвейер целиком

```
markdown-файл
    │
    ▼
parseMarkdown()       — построчный разбор в { title, lead, sections[] }
    │
    ▼
buildScene()          — для каждой секции считает id, раскладывает элементы,
    │                    расставляет ссылки-переходы
    ▼
JSON.stringify()      — сериализация в формат .excalidraw
```

Никаких зависимостей, только Node (`node:crypto`, `node:fs`). Всё в одном
файле `index.mjs`, ~600 строк.

## 1. Разбор markdown (`parseMarkdown`)

Простой построчный проход регэкспами, без библиотек:

- `# Заголовок` — первый такой заголовок становится `doc.title`. Всё, что идёт
  до первого `##`, попадает в `doc.lead` (вступительный текст на обзорном
  фрейме).
- `## Название` — открывает новую секцию (`doc.sections.push(...)`). Дальше
  всё складывается в неё, пока не встретится следующий `##`.
- `### Подзаголовок` — не новая секция, а помеченная строка
  `{kind: "subheading"}` внутри текущей.
- Строки списка (`-`, `*`, `1.`) и обычные абзацы — строки
  `{kind: "bullet" | "paragraph"}`.
- Кодовые блоки (` ``` `), горизонтальные линейки, символ `⁂` — пропускаются
  целиком (флажок `inFence`).
- `inlineToText()` чистит инлайновую разметку в каждой строке: убирает
  картинки (`![]()`), разворачивает `[текст](url)` → `текст`, убирает
  `` `код` ``, `**жирный**`, `*курсив*`, `__подчёркнутый__` и сноски вида
  `[1]`.

Результат — простая структура:

```js
{
  title: "Заголовок",
  lead: ["строка", "строка"],
  sections: [
    { title: "Название", items: [{ text: "...", kind: "bullet" }] },
  ],
}
```

Таблицы, картинки и код markdown не умеет превращать во что-то осмысленное на
холсте — такой контент нужно заранее переписать в обычный текст/списки.

## 2. Идентификаторы элементов (`makeId`)

Каждому элементу сцены нужен id, и он должен быть:

- **детерминированным** — при перегенерации сцены из того же (или слегка
  изменённого) markdown секция должна получить тот же id, иначе ссылки на неё
  осиротеют;
- **уникальным** — коллизия тихо ломает сцену: элементы с одинаковым id
  затирают друг друга, а ссылки начинают вести не туда.

Поэтому `makeId(key)` берёт `sha256(key)` и превращает первые 21 байт
дайджеста в строку из 21 символа алфавита Excalidraw (`0-9a-zA-Z-_`). Ключи —
человекочитаемые строки вида `"frame:section:2"` или `"overview:card:2"`, так
что при чтении сырого JSON видно, что чему соответствует.

Первая версия генератора использовала самодельный генератор на основе
`Math.imul` и индексировала 64-символьный алфавит младшими битами состояния.
Проблема в том, что младшие биты результата умножения по модулю 2³² зависят
только от младших битов входа — весь 21-символьный id определялся всего 6
битами. На примере из `example.md` это дало 67 элементов с 39 уникальными id.
Переход на sha256 (126 бит вместо 6) убрал проблему: документ на 2000 секций
даёт 16004 элемента и ровно 16004 уникальных id (проверено, см. `check.mjs`).

Отдельно есть `hash()` на FNV-1a — он не для id, а для `seed`/`versionNonce`,
косметических полей, отвечающих за «дрожание» линий от руки. Там коллизии
не страшны, поэтому используется более дешёвый алгоритм.

## 3. Раскладка сцены (`buildScene`)

**Обзорный фрейм** — один общий frame на весь документ:

- заголовок и вступление (`lead`) сверху;
- по центру — прямоугольник с названием документа;
- слева и справа от него — колонки карточек, по одной на секцию, цвета
  чередуются из `CARD_PALETTE` (6 пар цветов);
- от центра к каждой карточке — стрелка того же цвета.

**Фреймы секций** — под обзором, сеткой по `L.framesPerRow` (3) в ряд:

- заголовок секции цветом её карточки;
- список строк (`###` — крупнее и цветом, обычные пункты — с `•`);
- кнопка «← К обзору» внизу фрейма.

Высота каждого ряда фреймов считается по фактическому содержимому
(`bodyHeight`), так что длинная секция не наезжает на короткую в том же ряду.
Перенос текста (`wrap`) режет строки по числу символов, а размер текстового
блока (`textWidth`/`textHeight`) — это **прикидка** через
`CHAR_WIDTH_RATIO = 0.55`, а не точный замер шрифта: Excalidraw при импорте
ничего не перемеряет. Обычно этого достаточно, но на кириллице или длинных
словах текст иногда получается тесноватым — тогда поправляется руками на
холсте.

Все константы раскладки собраны в один объект `L` в начале файла:

```js
const L = {
  frameWidth: 1000,       // ширина фрейма секции
  frameGap: 160,          // отступ между фреймами
  framesPerRow: 3,        // фреймов секций в ряд
  padding: 48,
  cardWidth: 340,         // карточка в обзоре
  cardHeight: 96,
  cardGapY: 40,
  centerWidth: 380,       // центральный узел обзора
  centerHeight: 140,
  columnGap: 120,
  bulletFontSize: 18,
  headingFontSize: 32,
  cardFontSize: 20,
  leadFontSize: 16,
};
```

Поменять раскладку — значит поправить числа здесь, код структуры трогать не
нужно.

## 4. Как работает навигация — самая важная часть

Каждая карточка обзора получает
`link: "<base-url>/?element=<id фрейма секции>"`, а кнопка «назад» в каждой
секции — `link` на id обзорного фрейма.

Это не собственный формат генератора — это то, что реально понимает
Excalidraw:

- `packages/element/src/elementLink.ts` — `ELEMENT_LINK_KEY = "element"`,
  `isElementLink()` проверяет, что **хост ссылки совпадает с хостом текущей
  страницы** (`_url.host === window.location.host`);
- `packages/excalidraw/components/App.viewport.ts` — при клике достаёт id из
  `?element=`, ищет элемент через `getElementsFromId()` и зумит вьюпорт на
  его границы (для фрейма — на весь фрейм).

Отсюда требование `--base-url`: он должен буквально совпадать с адресом, на
котором сцену открываешь. Сгенерируешь под `https://draw.example.com`, а
откроешь через `file://` или на другом домене — Excalidraw не опознает ссылку
как переход внутри холста, и она откроется как обычная внешняя ссылка в новой
вкладке.

Стрелки на обзорном фрейме **не привязаны** к карточкам
(`startBinding`/`endBinding` — `null`): они нарисованы по координатам и не
потянутся, если подвинуть карточку руками. Один раз потянуть конец стрелки на
холсте — и Excalidraw привяжет её сам.

## 5. Валидация перед записью файла

`buildScene()` в конце проходит по всем сгенерированным элементам и **бросает
исключение**, если находит повторяющийся id — то есть сцена с испорченными
ссылками не запишется на диск, вместо этого упадёт с понятной ошибкой
`duplicate element id generated: ...`.

## Ограничения

- Таблицы, картинки, встроенный код и сноски — выбрасываются целиком, их
  нужно заранее переписать в обычный текст.
- Ровно два уровня вложенности: `##` (фрейм) и `###` (подзаголовок внутри
  фрейма). Более глубокая структура (`####` и ниже) не поддерживается.
- Раскладка не адаптируется под очень длинные секции — если пунктов в разделе
  много, фрейм просто станет выше; это ломает выравнивание сетки визуально
  (соседние фреймы в ряду будут ниже), но не структуру.
- Сцену нельзя открыть где угодно и получить рабочую навигацию — см. пункт
  про `--base-url` выше.

## Как запускать

Зависимостей нет — только Node (в репозитории уже требуется `>=18`, см.
`package.json`).

```bash
node tools/md-to-excalidraw/index.mjs <входной.md> \
  --base-url <https://ваш-excalidraw-хост> \
  [-o <выходной.excalidraw>]
```

Флаги:

| Флаг | Обязателен | Описание |
| --- | --- | --- |
| `<входной.md>` | да | Путь к markdown-файлу (позиционный аргумент). |
| `--base-url` | да | Хост, на котором сцена будет открыта. Должен совпадать буква в букву с адресом страницы — иначе переходы между фреймами не заработают (см. раздел про навигацию выше). |
| `-o`, `--output` | нет | Путь к выходному `.excalidraw`. По умолчанию — имя входного файла с заменённым расширением. |

Пример:

```bash
node tools/md-to-excalidraw/index.mjs report.md \
  --base-url https://draw.alexshein.com \
  -o report.excalidraw
```

При отсутствии `##`-секций во входном файле генератор откажется работать
(`no '## ' sections found, nothing to lay out as frames`) — значит,
исходный markdown ещё не в нужной форме (см. `README.md` про формат, либо
используйте скилл `md-to-excalidraw` для предварительной подготовки текста).

Как открыть результат: перетащить `.excalidraw`-файл на холст в браузере
(drag & drop) либо импортировать через меню Excalidraw.

Как перегенерировать после правки текста: просто вызвать команду ещё раз с
тем же `--base-url`. Вывод детерминирован, id секций не меняются, поэтому уже
расставленные вручную ссылки на других страницах (если такие есть) не
сломаются. **Но** любые правки, сделанные вручную прямо на холсте
(подвинутые карточки, перекрашенные блоки), при таком перезапуске потеряются
— генератор каждый раз пишет файл с нуля. Ручные доработки имеет смысл делать
в последнюю очередь, перед самой записью видео.

## Проверки

```bash
node --test tools/md-to-excalidraw/check.mjs
```

Файл называется `check.mjs`, а не `*.test.mjs`, намеренно: иначе его подхватит
`vitest` в `yarn test` и попробует выполнить как обычный тест проекта.

10 проверок: разбор markdown (включая пропуск кода и разворачивание
разметки), уникальность id, что каждая ссылка ведёт на существующий фрейм,
что у каждой секции есть карточка, которая на неё ссылается, что содержимое
не вылезает за границы своего фрейма, что фреймы не пересекаются между собой,
детерминированность вывода и отсутствие коллизий id на документе из 300+
секций.

## Пример

`example.md` в этой же папке — готовый пример входного файла:

```bash
node tools/md-to-excalidraw/index.mjs tools/md-to-excalidraw/example.md \
  --base-url https://draw.alexshein.com -o /tmp/example.excalidraw
```
