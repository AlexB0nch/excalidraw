# md-to-excalidraw

Этот скилл — не сам генератор, а слой перед ним. Генератор
(`tools/md-to-excalidraw/index.mjs`) принимает только markdown строго
определённой формы: один `#`, вступление, несколько `##`-разделов, опциональные
`###`-подзаголовки и списки. Реальные входы такими не бывают — это могут быть
отчёт на десять страниц, конспект встречи, план видео или просто «сделай схему
про X». Задача скилла — **сжать и переструктурировать** источник в нужную форму,
а затем прогнать через генератор.

Подробности устройства и полный список флагов — в
`tools/md-to-excalidraw/HOW_IT_WORKS.md` и `tools/md-to-excalidraw/README.md`.
Этот файл не дублирует их, только даёт алгоритм действий.

## Когда применять

- Пользователь просит диаграмму, схему, mind-map или раскадровку в Excalidraw
  из текста/отчёта/заметок.
- Особенно уместно, если упоминается запись видео, презентация, «показать и
  рассказать», навигация по схеме кликами — генератор именно под это заточен
  (клик по карточке зумит камеру на нужный фрейм).
- Не подходит, если нужен не самостоятельный холст, а разовая иллюстрация или
  правка уже существующей сцены — тогда проще рисовать/редактировать вручную.

## Целевая форма markdown

```markdown
# Заголовок схемы

Одна-две короткие фразы вступления. Не абзац на десять строк — это ляжет
на обзорный фрейм рядом с центральным узлом, места мало.

## Название раздела 1

### Необязательный подзаголовок
- короткий пункт
- ещё один

## Название раздела 2

- пункты без подзаголовков тоже ок
```

Жёсткие правила формата (генератор либо отбросит лишнее, либо не даст красиво
уместить текст, если их нарушить):

- Ровно два уровня вложенности: `##` — раздел (=фрейм), `###` — подзаголовок
  внутри раздела. `####` и глубже не поддерживаются вообще.
- Никаких таблиц, картинок, блоков кода, сносок `[1]` — они выбрасываются
  молча. Если в источнике есть таблица — перескажи её содержимое пунктами.
- Инлайновая разметка (`**жирный**`, `` `код` ``, ссылки) разворачивается в
  обычный текст — сохранится только слово, не форматирование.

## Ограничения по размеру (важно!)

Генератор не умеет мерить реальную ширину шрифта — он прикидывает по числу
символов и обрезает/переносит текст на глаз. Если превысить лимиты ниже, текст
не поместится в свой блок и наедет на соседний. Ориентируйся на них при
переписывании:

| Что | Примерный лимит | Где смотреть в коде |
| --- | --- | --- |
| Заголовок раздела (`##`) | ~30–34 символа | `wrap(section.title, 34)` |
| Заголовок карточки в обзоре | ~24–26 символов | `wrap(section.title, 26)` |
| Строка пункта списка | ~50–52 символа | `wrap(item.text, 52)` |
| Вступление на обзоре | 4–6 коротких строк, не абзац | `doc.lead.slice(0, 6)` |
| Число разделов (`##`) | 4–9 — это один-два ряда сетки 3×N и по 3-4 карточки в каждой из двух колонок обзора | `L.framesPerRow = 3` |

Если пунктов в разделе много (7+), раздели раздел на два — иначе фрейм
вытянется по высоте и собьёт выравнивание соседних фреймов в том же ряду
(не критично, но выглядит неряшливо на записи).

Если исходный текст длиннее — **сокращай смысл**, не пытайся впихнуть всё:
цель — материал для устной подачи с холста, а не полный текст на экране.
Цифры, ключевые тезисы, 2-4 пункта на раздел — этого обычно достаточно.

## Порядок действий

1. **Прочитай источник целиком** — файл, вставленный текст, PDF, что угодно.
2. **Выдели структуру**: главная мысль → заголовок и вступление; логические
   блоки → разделы (`##`). Если источник уже размечен `##`-заголовками —
   в первую очередь проверь их количество и длину пунктов под лимиты выше,
   не переписывай с нуля без необходимости.
3. **Сожми содержимое каждого раздела** до 2-5 пунктов с учётом лимитов по
   символам из таблицы. Не бойся терять детали — задача не пересказать
   документ дословно, а дать материал для навигации и устного комментария.
4. **Запиши получившийся markdown в файл** (например,
   `/tmp/<slug>.md` или рядом с исходником).
5. **Узнай `--base-url`** — это адрес, на котором пользователь откроет сцену
   (например, self-hosted Excalidraw из `COOLIFY.md`, если он есть в этом же
   репозитории/разговоре). Если адрес неизвестен и не находится по контексту
   разговора — спроси пользователя явно, не подставляй `excalidraw.com` или
   случайный домен: ссылки на переход между фреймами работают только если
   хост совпадает с тем, где сцена реально открыта (host-check в
   `isElementLink`, см. `HOW_IT_WORKS.md`).
6. **Запусти генератор**:
   ```bash
   node tools/md-to-excalidraw/index.mjs /tmp/<slug>.md \
     --base-url <тот самый хост> \
     -o <slug>.excalidraw
   ```
7. **Проверь вывод генератора** — он печатает число фреймов и элементов
   (`N section frames, M elements`) и падает с понятной ошибкой, если что-то
   не так (например, нет ни одного `##`-раздела, или обнаружена коллизия id —
   последнее означало бы баг в самом генераторе, не в тексте).
8. **Отдай файл пользователю** и опиши в одном-двух предложениях, что внутри
   (сколько разделов/фреймов), а не пересказывай генератор — детали устройства
   не нужны, если не спросили отдельно.

## Частые ошибки

- **Слишком длинные пункты списка** — переносятся криво, вылезают за карточку.
  Сокращай до сути, цифры и ключевые слова важнее полных предложений.
- **Взят чужой/дефолтный `--base-url`** — переходы между фреймами не работают,
  сцена откроется, но клики по карточкам будут уводить во внешние вкладки.
- **Слишком много разделов на один документ** (15+) — сетка станет длинной и
  неудобной для навигации с холста; лучше сделать два документа/две сцены,
  чем одну гигантскую.
- **Таблицы/код оставлены как есть** — генератор их просто выбросит, и раздел
  окажется пустым или урезанным. Перескажи их пунктами заранее.
